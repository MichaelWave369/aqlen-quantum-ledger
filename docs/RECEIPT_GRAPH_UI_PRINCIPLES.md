# Receipt Graph UI Principles

The AQLEN dashboard should make receipts reviewable, not merely attractive.

## Principles

1. **Every score must be traceable.**
   A readiness score should point back to the receipts, assumptions, and evidence that shaped it.

2. **Every warning should stay visible.**
   Claim-boundary text should not disappear when the user changes focus, filters, or views.

3. **Every edge should explain why it exists.**
   A graph edge should carry a relationship type and a note.

4. **Every evidence lane should stay separate until merged by review.**
   Different papers, labs, and device classes should not be collapsed into one unsupported mega-claim.

5. **Every UI mode should preserve humility.**
   The dashboard is for research intelligence and auditability, not hype.

## First UI modes

- Summary view
- Score trace view
- Evidence impact view
- Noise-to-calibration view
- Module influence view

## Future UI modes

- Manufacturing lineage view
- Drift over time view
- QEC readiness breakdown
- Source-status review
- Human-review queue
