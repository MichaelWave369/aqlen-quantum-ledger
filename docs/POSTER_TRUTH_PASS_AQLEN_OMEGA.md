# AQLEN Ω Poster Truth Pass

Status: v0.2 concept/poster guidance

Purpose: translate the Richie-inspired AQLEN Ω poster into public-safe, evidence-aware architecture copy.

## Verdict

The poster is useful as internal concept art and product-direction inspiration. Public use requires claim discipline.

Best retained thesis:

> AQLEN does not only correct errors. It remembers where the errors came from.

Safe classification:

- Concept poster
- Product architecture visual
- Evidence-aware research scaffold
- Not scientific proof
- Not a quantum hardware announcement

## Core public-safe positioning

Use:

> AQLEN Ω is a proposed ledger and intelligence layer for manufacturable quantum systems.

Use:

> From hardware → error → calibration → intelligence.

Use:

> AQLEN tracks hardware provenance, error origin, calibration action, and readiness assessment.

Avoid:

> The world’s first quantum evolution network.

Avoid:

> Practical quantum computing is solved.

Avoid:

> Autonomous quantum science without human review.

Avoid:

> Limitless quantum intelligence.

## Evidence-lane handling

Keep these as separate lanes. Do not merge them into one claim.

### Evidence lane 1 — UNSW / Morello line

Safe poster copy:

> Single-qubit gate fidelity >99.9%.

Bounded meaning:

- Useful anchor for silicon-spin control fidelity.
- Does not imply complete fault-tolerant deployment.

### Evidence lane 2 — Diraq / imec / foundry line

Safe poster copy:

> 300-mm foundry silicon spin-qubit unit cells.
> 1- and 2-qubit gate fidelities >99%.
> SPAM up to 99.9%.

Bounded meaning:

- Useful anchor for manufacturability, wafer-scale variation tracking, and foundry-style quality receipts.
- Does not imply every commercial fab can already mass-produce useful quantum chips.

### Evidence lane 3 — 11-qubit atom processor line

Safe poster copy:

> Strong evidence lane for ~99.9% two-qubit silicon operation.

Bounded meaning:

- Useful anchor for high-fidelity silicon atom-processor research.
- Should not be blended with the 300-mm foundry claim unless a specific source supports that merge.

## Public-release checklist

Before publishing a poster:

- Check each technical number against a source anchor.
- Separate evidence lanes instead of merging them.
- Avoid “solved,” “proof,” “world’s first,” and “limitless” claims.
- Label the visual as concept architecture.
- Make sure the claim-boundary panel is visible.
- Keep human-review language when AI-assisted search is mentioned.
