# AQLEN Dashboard Renderer v0.1

Status: prototype  
Scope: local static dashboard renderer for the AQLEN receipt graph dashboard export

## Purpose

The renderer turns a dashboard export payload into a human-readable graph inspection surface.

It is intentionally small and local-first. The goal is not a finished product UI yet. The goal is to prove that AQLEN can move from:

```text
evidence anchor -> qubit receipt -> noise event -> calibration receipt -> readiness score -> architecture module
```

into a visual inspection workflow with visible claim boundaries.

## Files

```text
dashboard/receipt_graph_renderer.html
dashboard/receipt_graph_dashboard_demo.json
examples/receipt_graph_dashboard_export_commands.json
```

## How to run

From the repository root:

```bash
python -m http.server 8000
```

Then open:

```text
http://localhost:8000/dashboard/receipt_graph_renderer.html
```

The renderer tries to load:

```text
dashboard/receipt_graph_dashboard_demo.json
```

You can also upload or paste a JSON payload generated by:

```bash
python tools/receipt_graph_dashboard_export.py export \
  --graph examples/receipt_graph_minimal.json \
  --focus score-demo-001 \
  --depth 6 \
  --out dashboard/receipt_graph_dashboard_demo.json
```

## What it shows

- Summary cards
- Node cards grouped by badge/type
- Edge cards with source, target, label, and note
- Boundary cards
- Global claim boundary banner
- Focus trace highlighting

## Claim boundary behavior

The renderer should always preserve visible boundary context. If an exported node has warnings or claim-boundary text, the UI displays it directly on the node card or in the boundary panel.

This keeps AQLEN from becoming a black-box hype dashboard. The user should see what each score means, what it does not mean, and which claims are still only research-direction anchors.

## v0.2 renderer target

The next renderer pass should add:

1. Real graph layout instead of card grid only.
2. Click-to-focus node behavior.
3. Search by node id, label, type, and status.
4. Filter by node group.
5. Export focused trace as JSON.
6. A visible source-status legend.
7. Dashboard test fixtures.

## Product note

This renderer is the first UI bridge between AQLEN's receipt graph and a future dashboard. It should remain evidence-aware, local-first, and human-reviewed.
